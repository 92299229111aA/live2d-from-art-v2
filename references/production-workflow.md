# 一句话制作协议

用户说“用此技能把附件做成可直播的半身 Live2D”时，默认目标为 VTube Studio、OBS 透明叠加、保留身份、浅角度 XYZ、独立眼球与眨眼、开合嘴、可见的身体随动和耳发次级运动。沿用输入分辨率，不把 AI 放大当作细节恢复。无特殊约束无需逐阶段询问继续；显式暂停、阶段限制和用户确认要求优先。

## 0. 开工与恢复

先读项目状态和实际文件，不因一次“继续”重建项目。建立 project.json：源文件 SHA256、目标平台、画布、左右命名约定、默认姿态、允许重绘范围、预期直播像素尺寸、依赖版本、当前阶段、阻塞项、最近有效构建及待办。

先检查图像工具、Python 依赖、Core 合法来源、浏览器和 VTS 可控性。缺少 VTS 不阻止独立的素材/Core 工作，但必须提前说明最终验收限制。不把用户机器路径写进共享技能。

源文件按字节复制并校验哈希；RGB 原图不能声称保留了原生 Alpha。采用角色相关的项目目录：original、master、parts、underpaint、layout、authoring、runtime、preview、vts、qa、release；已有编号目录保持不动。

## 1. 先解决姿态和直播构图

默认保留可见像素和原姿态。检查举手、前伸手臂、头部倾斜、衣袖遮挡、长耳和长袖对构图的影响，记录 blocking-occlusions.md。

若用户指定自然垂臂，先完成局部手臂/袖子姿态稿和可见遮挡补全，再绑定；不把转动刚性原图块当成换姿。若用户没有指定，原姿态明显妨碍目标时，只询问这一项关键选择，同时继续其他基准工作。换姿需要的可见重绘不能伪称“仅隐藏区补绘”。

保存原画姿态 neutral_reference；另保存 tracking_rest 参数预设。原图张嘴时，原画基准与直播闭嘴休息态是两个不同状态。RESET 使用明确的预设值（眼开通常为 1），不是把所有参数机械归零。

在最终 OBS 小头像尺度预览胸像/半身构图；不要用“全画布能容纳所有长袖”代替直播构图合理性。脸部特写允许有意裁掉袖子，半身视图需说明保留范围。

## 2. 素材与静态门禁

按动作需求拆层，不追求层数。每层记录 name、texture、x/y、width/height、draw_order、visibility、parent、anchor，共享全局画布。不得逐层缩放或居中。

眼白、虹膜、瞳孔、高光独立；眼开口遮罩裁切虹膜，闭眼不能压扁整颗眼球。眉毛/睫毛/嘴像素只能有明确的可见归属，避免刘海中留下第二条眉。补绘仅覆盖运动揭露区域；没有授权不重画可见脸。

同位置合成、脸部放大、深浅底、透明边缘检查通过再绑定。数值比较记录包含与排除的区域，不能用遮罩排除缺陷后报告“全图零误差”。

## 3. 先做最小垂直切片

静态 MOC → 实际 Core → 同尺度静态视觉检查 → 若可用，立刻在 VTS 加载。这比所有参数做完后才发现目标运行时不兼容更便宜。

随后 Eyes → Mouth → Brows → Head → Body → Hair/Ears/Tails → Sleeves/Accessories → Idle。只构建当前角色有的部件；每个功能保留检查点，跑相关单参数端点、中间值和必要组合，不每次重跑所有历史测试。

Body 阶段就检查最终直播尺寸下是否可感知。必须有腰部锚、身体带头、肩胸呼吸、袖子跟随；有限顶点变化只能证明绑定，不能证明自然运动。没有可见动作时优先查映射范围、父子变形叠加、平滑和补底安全量，不能靠随机大幅摇晃遮掩。

## 4. 同一运行资源贯穿验收

以实际导出的 physics3/motion3/exp3 为验收对象。浏览器优先使用兼容 SDK 的相同资源；自定义弹簧只能标记为预演，不能给导出的物理 PASS。VTS 自动映射不是最终映射：核对每个输出范围与 MOC 范围，特别是眼开、嘴开和浅转头；检查轴向、左右、饱和、平滑和休息态。

耳根→中段→末端、马尾根→梢形成连续弯曲和滞后；急停后衰减。故障出现时关闭 idle/physics/自动动作，恢复基准，逐参数定位。

面捕参数注入可测映射，但不能冒充真人摄像头测试。提前询问用户是否能配合一次五分钟动作会话；没有回复不启动依赖配合的验收。记录真实开始/结束时间、输入设备、追踪状态、画面证据及覆盖动作。只有等待五分钟不等于压力测试。

## 5. 交付

用 pack_runtime.py 从清单白名单构建全新包，不复制整个工程。VTS 的 vtube.json 若使用则纳入，并检查其模型/动作/图标/热键文件引用。生成哈希、构建 ID 和证据索引。任何后续素材或参数修改都使旧的相关验证失效。

最终 PSD 应与最终布局同步；否则明确标为历史快照，不作为最终源工程。不得声称提供了 cmo3。完整源码与运行包分离。

按 acceptance.md 写最终报告；record_review.py 记录证据后，release_gate.py 校验声明的完整性和资产新鲜度。它不会自动判断画面自然程度。

默认持续完成可执行工作；只有真实外部依赖、用户明确的视觉决策或最终人工面捕需要交互。不可承诺任意原图无人工判断即可产出高质量成品。
