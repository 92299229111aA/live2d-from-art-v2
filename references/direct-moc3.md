# 直接用代码构造 Live2D

## 文件边界

- PSD / 分层 PNG：美术输入。
- `.cmo3`：Cubism Editor 编辑工程；本案例没有生成它。
- `.moc3`：供 Cubism Core 加载的二进制运行模型，包含网格、参数和形变数据。不是把 JSON 改后缀。
- `.model3.json`：引用 MOC3、纹理、动作、表情、物理等文件的入口。
- `.motion3.json` / `.exp3.json` / `.physics3.json`：时间曲线、表情参数及物理配置。

有 Cubism 工程需求时优先正规编辑/导出流程。代码方案交付的是“制作代码 + 素材 + 运行模型”，不能承诺 Editor 可反向编辑。

## 本案例的已验证实现

`assets/worked-example/character/build_moc.py` 使用相邻 `tooling/py-moc3/src` 的实验性序列化器，写出MOC v4，已在本次项目的Web Core5.1和原生Core5.0做过加载/结构检查。第三方序列化库的 MIT 许可随包保留；它不代表 Live2D SDK/Core 的许可。

这些细节针对随包快照，升级库时不能盲目重复修补：

- `SECTION_LAYOUT` 的41/44、82/83对调，修正该版本索引/顶点计数映射。
- 案例画布1086×1448、原点543/724、ppu1000；顶点坐标为 `(pixel - origin)/ppu`。
- 每片7×11顶点是演示网格，不适合所有眼睑/嘴唇轮廓。精细角色应按轮廓、折线和形变需要布点。
- 图集4096，边缘外扩2px防止采样暗边；UV使用atlas y/height，当前加载路径不再翻转Y。
- 关键形数组的展开顺序与参数轴顺序必须一致；当前最内层局部参数变化最快。多轴组合数量随轴数量相乘，避免把每个参数绑定到每片网格。
- 正确填写参数轴、binding bands、keyform offsets/counts、mask indices、draw orders及padding；不要只检验文件头。
- 案例大部分动作烘焙为关键形，保留的rotation deformer不是所有网格的实际父级；不能从其存在推断有完整层级绑定。

## 增量构建

先写静态网格/纹理并通过Core加载；随后每加一类参数，验证默认值仍拼回原图，再检查极值和组合。

眼睛开合应主要改变眼睑开口遮罩，不能把整颗虹膜纵向压扁。闭眼线在闭合时显现，皮肤补层覆盖原有眼部。嘴张开时保持上唇相对稳定，让下唇和口腔协调展开，嘴角和下巴不要跟着整块下坠。

头部小角度转动要协调脸、鼻、眉、眼、头发，同时在颈部渐变到稳定锚点。案例使用近似深度与颈部权重，支持浅转脸；不能从单张正脸推导完整侧脸。身体重心以腰部为锚，肩部形变不能拉动脸；发根不动、发梢逐渐增大运动。

若发现 MOC 无法加载：先检查清单路径，再看Core一致性/加载结果，然后检查计数、偏移、索引、关键形轴和版本兼容。不要通过替换成别人的角色MOC再贴新图来声称完成原角色建模。

## 依赖

原画脚本需要 Pillow、NumPy、OpenCV；PSD另需psd-tools；构造器用随包MIT源码。网页需要来源与许可明确的 Cubism Core、Pixi及兼容的Live2D适配层。案例vendor不随Skill复制；从用户已有合法安装或官方来源取得匹配版本，并记录版本。若需要下载/确认当前SDK接口，查官方文档，不能把实验格式修补称为官方接口。
